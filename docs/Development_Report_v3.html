2. 목표 및 배경

  • 엑셀이나 다른 앱에 흩어진 독서 기록을 한눈에 보이는 책장으로 바꾸는 것이 출발점입니다. 한 해가 한 선반이고, 쪽수가 두께, 분야가 책등 무늬, 표지 색이 책등 색이 됩니다.
  • 핵심 가치
    • 보는 즐거움: 숫자 목록 대신 실제 책장처럼 꽂힌 책등, 꺼내면 옆 책을 밀며 비스듬히 돌아 나오는 3D 책, 연도별 나이테.
    • 빠른 기록: ISBN·제목 검색으로 책 한 권 등록을 10초 안에.
    • 첫날부터 여러 해: 기존 기록을 CSV로 가져와 바로 여러 해의 책장을 채움.
    • 돌아보기: 연도끼리 비교하고, 연말에 그해의 책·한 줄 회고·공유용 회고 카드를 만듦.
    • 이어 가기: 올해 목표 권수를 정하고 책장·나이테에서 진행률을 확인.
    • 찾기(v3): 책장이 커져도 전체 목록에서 제목·저자·연도·분야·별점으로 바로 찾음.
  • 운영 제약: 새 서비스를 늘리지 않고 GitHub(Pages)와 Supabase 무료 요금제 안에서 운영합니다. Supabase 프로젝트는 기존 독서 앱과 함께 쓰므로 bookchronicle 스키마만 다룹니다.
  • 하지 않는 것: 오프라인 사용, 여러 사용자·소셜 기능, 기존 앱과의 데이터 교환, 인용문·독서 노트 중심 기능(P2), AI 추천.

3. 주요 기능

로그인

  • 이메일 + 비밀번호(회원 가입 화면 없음). 기존 독서 앱과 같은 계정.
  • 배경 그림(v3): 책장과 "북크로니클 / BOOK CHRONICLE" 제목이 그려진 그림 위에 로그인 카드. 가로 화면은 그림이 화면을 채우고, 세로 화면은 그림을 위에 크게 놓음.
  • 로그인이 끝났을 때 안내(v3): 다른 곳에서 전체 로그아웃되어 서버의 세션이 사라지면, 한 번 새로 받아 보고 안 되면 로그인 화면에 "로그인이 끝났어요. 다시 로그인해 주세요"를 보여 줌.
  • 로그아웃은 이 브라우저만(v3). 기존 독서 앱과 다른 기기의 로그인은 그대로.

책장 홈 (#/)

  • 연도별 책장(올해는 비어 있어도 표시), 맨 위 "읽는 중" 선반, 맨 아래 "중단한 책"·"연도 미상" 선반.
  • 생성형 책등: 쪽수 → 두께, 분야 → 무늬(하드커버·페이퍼백·라벨형), 표지 → 색, 제목은 말줄임 없이 모두 표시(Pretendard).
  • 표지 질감 모드: 흐린 표지를 깐 책등(표지가 없는 책은 생성형).
  • 상단 도구(v3 정리): 윗줄은 검색창(+ 지난해 접기), 아랫줄은 정렬 칩 6가지 + 강조 보기. 두 줄의 좌우 끝을 맞춤.
  • 정렬 6가지: 내 순서(끌어 옮기기, Alt+←→), 완독일순, 색상순, 분야순, 별점순, 쪽수순.
  • 다른 해 책장으로 끌어 옮기기: 놓으면 완독일 확인 창(월·일 유지, 연도만 바꿔 미리 채움). 화면 끝에서 자동 스크롤.
  • 꺼내 보기 3D(v3 다듬기): 마우스를 올리면 살짝 들리고, 누르면 오른쪽 책들이 옆으로 밀리며 책이 62° 돌아 실제 표지가 비스듬히 보임. 위에서 조금 내려다보는 시점이라 책 윗면(종이 결)이 보이고, 돌아간 책등은 어둡게, 표지에는 접히는 홈 그림자와 광택. 줄 끝 책은 왼쪽으로 당겨 자리를 만듦. 꺼낸 책(책등·표지·윗면 어디든)을 다시 누르면 제자리로 꽂힘. 움직임 줄이기에서도 3D 모습은 보이고 애니메이션만 꺼짐.
  • 그해의 책 트로피 배지(v3): 책등 위 끝에 밝은 금색 원 + 트로피 아이콘(이전의 책갈피 끈을 바꿈).
  • 강조 보기(별점 4.5 이상 또는 분야), 지난해 접기(책등 색 띠), 읽는 중 책 기대어 놓기.
  • 올해 요약, "한눈에", 올해의 나이테, 목표 권수 진행률(요약·진행 막대·나이테 바깥 호).

전체 목록 (#/list, v3 새 화면)

  • 기록 하나가 한 줄(다시 읽은 책은 "2회째" 표시). 읽는 중·중단 기록도 포함.
  • 내 책장 안에서 제목·저자 검색(대소문자·띄어쓰기 무시).
  • 거르기: 연도(연도 미상·읽는 중·중단 포함), 분야, 별점(4.5 이상·4 이상·3 이하·없음), 다시 읽은 책만(같은 책 기록을 읽은 순서로 붙여서).
  • 정렬: 최근에 읽은 순·오래된 순·제목 가나다순·별점 높은 순·두꺼운 순. 요약 줄("25권 · 8,508쪽 · 평균 별점 4.0")은 거른 결과를 따라감.
  • 넓으면 표(제목·저자·분야·완독·별점·쪽수), 좁으면 두 줄 카드. 100줄씩 더 보기, ↑↓ 키보드.
  • 줄을 누르면 책장과 같은 상세 패널(고치기·다시 읽은 기록·그해의 책). 다른 메뉴에 다녀와도 검색어·거르기 유지.

책 꽂기

  • 카카오 책 검색(제목·저자) + 국립중앙도서관 ISBN 서지정보(쪽수·KDC 분류) 자동 입력.
  • 검색 함수 미리 깨우기: 책 찾기 칸에 처음 입력할 때 함수를 미리 깨워 첫 검색의 콜드 스타트를 줄임.
  • 표지에서 책등 색 3가지(바탕·띠·강조) 추출, 직접 바꾸기 가능. 바코드 스캔(휴대폰 카메라로 ISBN).
  • 별 5개를 눌러 채우는 0.5 단위 별점, 분야 24개 + 직접 입력, 수동 입력 전환.

가져오기·백업 (#/import)

  • CSV 가져오기: 인코딩 자동 판별(UTF-8/CP949), 열 맞추기 추천, 다양한 날짜·별점 형식, Goodreads 형식 인식, 보충 조회(동시 2건), 중복 처리.
  • JSON 백업·복원(덮어쓰기/합치기, 표지 포함 선택, 목표 권수 포함), CSV 내보내기(UTF-8 BOM), 30일 백업 알림.

연도 비교 (#/compare)

  • 2~5개 연도의 지표 카드 6개와 증감, 권수 카드에 목표·달성 표시.
  • 월별 선 그래프(권수·쪽수, 누적), 분야 비중 100% 누적 막대, 연도별 추이 막대, 표로 보기.

연말 회고 (#/recap/2026)

  • 그해의 책 1~3위(고른 순서가 순위, 올리기·내리기·빼기, 별점 기반 후보 제안), 한 줄 회고(80자), 12월 안내.
  • 회고 카드: 템플릿 3가지(책장형·월별형·분야형) × 크기 3가지 × 테마 3가지, 항목 선택, PNG 저장·공유.

설정 (#/settings)

  • 테마(기기 설정·서재·종이)·책등 스타일(계정에 저장), 움직임 줄이기(기기별), 올해 목표 권수.
  • 분야별 책등 무늬, 분야 이름 바꾸기·합치기, 도서 검색 연결 확인, 백업 바로 가기, 계정·로그아웃.

화면 문구 (v3 정리)

  • 모든 화면 문구를 맞춤법 검사로 다듬음: 존댓말 끝맺음 통일, "취소"·"기록 고치기" 등 용어 통일, 칸·버튼 이름 정리.
  • 책 제목·분야처럼 바뀌는 낱말 뒤의 조사를 받침에 맞게 고름(josa: 「데미안」을 / 「코스모스」를, 숫자·영문은 읽는 소리로 판단).

4. 기술 스택 및 아키텍처

구분선택이유
프론트엔드Svelte 5(runes) + TypeScript 6.0 + Vite 8작은 번들, 반응형 상태가 단순함. TS는 typescript-eslint 지원 범위 때문에 6.0
라우팅직접 만든 해시 라우터화면이 7개뿐이고 GitHub Pages는 서버 라우팅이 없음
백엔드Supabase(Auth·Postgres·Storage·Edge Functions)이미 쓰는 무료 프로젝트. bookchronicle 스키마로 분리
도서 정보카카오 책 검색 + 국립중앙도서관 ISBN 서지정보알라딘 Open API가 2026-10-30에 종료(결정 0008)
3D 책CSS 3D 변환(preserve-3d, 원근 1100px)라이브러리 없이 책등·표지·윗면 세 면을 돌림. 옆 책 밀기 거리는 순수 함수로 계산
그래프Chart.js(연도 비교 화면에서만 지연 로드, 약 57KB gzip)구현 계획에 정한 라이브러리
회고 카드Canvas 2D(직접 그림)템플릿·크기·테마 조합을 한 함수로 그리고 PNG로 저장
CSVPapa Parse따옴표·줄바꿈이 섞인 CSV를 안정적으로 읽음
바코드BarcodeDetector → 없으면 ZXing(스캔할 때만 로드)아이폰 사파리에는 내장 인식기가 없음
배포GitHub Actions → GitHub Pagesmain에 올리면 자동 배포
테스트Vitest(단위), Playwright(E2E), axe-core(접근성)계산은 단위 테스트, 화면 흐름은 가짜 Supabase로 E2E

 ├─ 테이블: books, readings, years, settings, aladin_cache  (모두 RLS "본인 행만")
 ├─ Storage: bookchronicle-covers (비공개, 표지·질감)
 └─ Edge Function: bookchronicle-books  ──▶ 카카오 / 국립중앙도서관 (API 키는 secrets에만)
  • 데이터 모델: books(책 정보·책등 팔레트·표지 경로) 1 : N readings(독서 기록, 완독 1회 = 책등 1개). readings.year는 완독일에서 계산하는 생성 열. years(그해의 책 1~3위 배열·한 줄 회고·목표 권수), settings(테마·책등 스타일·무늬 매핑).
  • 마이그레이션: 0001~0006(v3에서 DB 변경 없음).
  • 상태 관리: 책장 데이터는 library.svelte.ts 한곳에 두고, 저장 후에는 네 테이블을 다시 불러와 화면과 DB가 어긋나지 않게 합니다. 전체 목록은 이 책장 데이터에서 줄을 만들기 때문에 따로 불러오지 않습니다.
  • 스타일: 색·글꼴·간격은 tokens.css·themes.css의 CSS 변수만 씁니다. 테마와 상관없는 값(트로피 배지 금색, 로그인 배경 바탕색)은 tokens.css에 둡니다.

8. 보안/성능 고려사항

보안

  • 공유 Supabase 프로젝트: bookchronicle 스키마·bookchronicle-covers 버킷·bookchronicle- 함수만 다루고, 기존 앱 자원은 읽지도 고치지도 않음.
  • 모든 테이블·버킷에 RLS "본인 행만"(user_id = (select auth.uid())). npm run check:rls로 원격 점검.
  • 브라우저에는 Supabase 주소와 publishable 키만. 도서 API 키는 supabase secrets에만.
  • Edge Function: 허용한 Origin에만 CORS, 로그인 + 앱 주인 ID 확인(401/403).
  • (v3) 로그인 문제를 진단할 때 Supabase 로그(함수 응답 코드, Auth의 session_not_found)와 bookchronicle.books의 사용자 ID만 읽기 전용으로 조회했습니다. 비밀 값은 읽거나 출력하지 않았습니다.
  • (v3) 로그아웃 범위를 이 브라우저로 좁혀, 북크로니클이 기존 앱의 로그인을 끊지 않습니다. Auth 설정은 바꾸지 않았습니다.
  • GitHub 저장소: Secret Protection과 Push protection을 켬.

성능

  • 책 1,000권(10년치)에서 로그인 → 모든 책장 표시 약 1.1~1.4초(목표 2초), 스크롤 중 50ms 넘는 작업 없음. 3D 윗면은 꺼낸 책에만 그려 이 수치를 지킴.
  • 전체 목록은 처음 100줄만 그리고 "더 보기"로 늘림. 목록 계산은 이미 불러온 책장 데이터를 쓰므로 추가 요청이 없음.
  • 무거운 라이브러리는 필요한 화면에서만 지연 로드(Chart.js, ZXing). 로그인 배경 그림은 WebP(약 146KB).

11. 알려진 한계

  • 국립중앙도서관 인증키 승인 대기: 그전까지 검색으로 꽂은 책은 쪽수가 비어 분야 평균으로 추정해 그립니다.
  • 기존 앱에서 로그아웃하면 북크로니클도 다시 로그인해야 함: 기존 앱의 로그아웃이 전체 범위라서입니다. 이제는 엉뚱한 안내 대신 로그인 화면으로 돌아가며, 기존 앱 코드는 공유 규칙상 바꾸지 않습니다.
  • 실기기 확인이 남음: 바코드 스캔, 홈 화면 추가, 표지 질감 모드, 회고 카드 공유, 휴대폰에서 3D 꺼내 보기와 목록 줄 누르기.
  • 쓰지 않는 그림 파일: public/book-chronicle-splash-screen.png(약 1.8MB)가 저장소와 배포본에 남아 있습니다. 앱은 WebP만 씁니다.
  • 목록 거르기는 새로 고침하면 처음 상태: 주소에 담지 않았습니다.
  • 휴대폰·키보드로는 다른 해로 끌어 옮기기 불가: "기록 고치기"로 날짜를 바꿉니다.
  • 판형(책 크기) 없음: 책등 높이는 책 ID 기반 난수입니다.
  • 로컬 DB·Edge Function 실행 환경 없음: 마이그레이션은 원격에서 바로, 함수는 Vitest 흉내와 배포 후 점검으로 확인합니다.
  • 문서 불일치: PRD 6.7·DESIGN 6.2의 제목 숨김 규칙, 설정 저장 범위, 그해의 책 3권·목표 권수·카드 템플릿·전체 목록·3D 다듬기 등이 PRD에는 아직 반영되지 않았습니다(결정 기록 0009~0021이 우선). DESIGN은 트로피 배지(6.5)만 고쳤고, 7.4의 로그인 카드 작은 책장 그림 설명은 남아 있습니다.
  • E2E 한 개가 가끔 실패: 전체 실행에서 journey.spec.ts나 성능 테스트가 드물게 실패하고 다시 돌리면 통과합니다(타이밍 영향).

  2. 쓰지 않는 PNG 지우기: public/book-chronicle-splash-screen.png를 지워 배포본을 1.8MB 줄이기.
  3. PRD·DESIGN 문서 정리: 결정 0009~0021 내용을 기획서·디자인 문서에 반영(특히 PRD F8 전체 목록, DESIGN 7.4 로그인 카드).
  4. 실기기 점검 기록: 휴대폰에서 3D 꺼내 보기, 목록 줄 누르기, 로그인 배경, 바코드 스캔을 확인하고 docs/screen-checklist.md에 기록.

여유 있으면

  • 목록에서 바로 보내기: 거른 결과만 CSV로 내보내기(예: "2025년 별 5개 책").
  • 목록 거르기를 주소에 담기: #/list?year=2025&rating=gte4.5처럼 새로 고침해도 남고 즐겨찾기도 되게.
  • 목표 페이스 안내: "이대로면 연말까지 약 14권", 목표까지 한 달에 몇 권이 필요한지.
  • 그해의 책 배지에 순위 표시: 1·2·3위를 금·은·동 배지로 나누거나 작은 숫자를 붙이기.
  • 키보드로 다른 해로 옮기기: 책등에서 단축키로 옮기기 창 열기.
  • 회고 카드 템플릿 더하기: 목표 달성 카드, 별점 분포 카드.

아이디어 수준

  • 인용문·독서 노트(P2): 책마다 밑줄 친 문장을 모아 보는 공책.
  • 시리즈 묶기: 같은 시리즈 책등을 이어 붙여 보여 주기.
  • 연도 타임랩스: 해마다 책장이 채워지는 모습을 애니메이션으로.
  • 스플래시 화면: 앱을 처음 열 때 로그인 배경 그림과 '들어가기' 버튼만 있는 시작 화면(로그인된 상태에서도).
